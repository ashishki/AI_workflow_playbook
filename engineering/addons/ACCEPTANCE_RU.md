# Приёмка инженерных дополнений

Не смешивать корректность упаковки, способность host применить skill и пользу
метода. Проводить в отдельных тестовых проектах, не production. Новые зависимости,
доступы и платные запуски требуют применимого разрешения. Сохранять неудачи.

## 1. Offline

```bash
python -m unittest discover -s engineering/addons -p "test_*.py" -v
python engineering/addons/bundle.py check
python engineering/addons/bundle.py doctor
python distribution/native/sync_runtime.py --check
python -m unittest discover -s tests/vnext -v
python tools/vnext_check.py --root .
```

Проверить build/install/verify для обеих сред на пустых папках. Повторная установка,
изменённый skill, конфликт чужой папки и симлинк должны остановиться без перезаписи.
Исторический провал baseline фиксировать отдельно; не менять frozen evidence/locks.

## 2. Live host acceptance — отдельно Codex и Claude Code

Записать exact commit, host/model/version, доступы, исходные задания, лимит времени
и расходов. При отсутствии host или разрешения — NOT_RUN/BLOCKED. Не имитировать.
Дубликаты skills и глобальные инструкции проверить до опыта, не читать секреты.

| Сценарий | Независимо наблюдаемый результат |
|---|---|
| Явный вызов каждого из четырёх skills | Host загрузил правильную установленную версию, не одноимённую глобальную |
| Обычная маленькая задача без вызова | Нет обязательного опроса, браузера, heavy или команды субагентов |
| Разбор заранее известного diff | Найдены изменения поведения, существенный риск и пробел проверки; ссылки верны; код не менялся |
| Неоднозначное правило | Вопрос только о блокирующем решении; не выдумано правило; обсуждение не изменяет файлы |
| Новый сеанс | Проверяется реальная ревизия/состояние; не требуется пересказывать весь чат |

Не использовать другую модель как единственное основание правильности. Для разбора
изменений заранее приготовить эталонные факты/риск, известные владельцу или проверяющему.
Для модели использовать существующий Harness Lab, а не писать новый оркестратор.

## 3. Browser

Безопасный локальный fixture: `fixtures/browser.html`. Никаких внешних ресурсов.
Из отдельного терминала в корне репозитория можно запустить на свободном порту:

```bash
python -m http.server 8765 --bind 127.0.0.1 --directory engineering/addons/fixtures
```

Если порт занят — выбрать другой, не останавливать неизвестный процесс. Открыть
`http://127.0.0.1:8765/browser.html` colocated-браузером. Без tunnel/publication.
Проверить пустое имя (ошибка), добавление тестовой записи, повтор (без дубля), reload
(сохранение), имитацию сбоя (нет новой записи), narrow viewport и скриншот. Проверяющий
должен открыть изображение. Fixture сам по себе не browser PASS.
Сравнить существующий browser path и agent-browser на одинаковой версии/состоянии,
с чистыми сессиями; записать версии CLI/browser. Закрыть только свой сервер/сессию.

## 4. heavy — Linux/macOS, отдельно от skill discovery

В тестовой папке запустить несколько коротких задач с одинаковыми slots/pool/dir.
Записать реальные start/end/PID, проверить максимум одновременных процессов, передачу
ненулевого exit, очередь с `CI=1`, queue timeout и отмену своего process group.
Проверить nested bypass; kill wrapper отдельно не считать остановкой потомков.
Не нагружать shared VPS до отказа и не использовать чужие реальные процессы.
Затем сравнить разрешённый типовой набор тестов/сборок с очередью и без неё. Считать
ожидание, wall time, peak memory/pressure если измеримо, ошибки, отзывчивость и помощь
владельца. Сохранить все попытки и лимиты. При отсутствии contention можно отказаться.

## 5. Решение отдельно по каждому дополнению и host

Для Codex сравнивать Codex baseline vs Codex+addon; для Claude аналогично. Не
приписывать эффект смене модели, дополнительному экспертному часу или бюджету.
Начать с трёх сопоставимых повторов в чередующемся порядке; это пилот, не универсальное
доказательство. Замерять время человека, исправления, остаточные ошибки, полные затраты
и качество результата. Unknown cost/time = null, не 0. Техническое сравнение инструментов
и модельный эффект skills — разные эксперименты.

Отчёт: `reports/engineering-addons/<run-id>/REPORT_RU.md` и `results.json` после
проверки приватности. Сырые логи/скриншоты — в `.playbook-artifacts/`, не в Git по умолчанию.
JSON для каждой пары host/addon: revision, versions, scenario, status
(PASS/FAIL/BLOCKED/NOT_RUN), evidence, human_minutes, wall_seconds, cost_usd,
remaining_defects, comparison_valid, decision и limitations. Неисполненные поля null.
Решение: ENABLE_CONDITIONALLY / KEEP_EXPERIMENTAL / REJECT. Merge исходников не
означает доказанную пользу, установленный CLI или автоматический rollout.
