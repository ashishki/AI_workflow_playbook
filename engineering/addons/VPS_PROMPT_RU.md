# Проверка и интеграция — только после приёмки

В AI_workflow_playbook прочитай AGENTS.md и engineering/addons/README_RU.md.
Рабочая ветка: feature/engineering-addons-codex-claude-20261027.
Сохрани чужие изменения; fetch без reset --hard. Проверь фактическую основную
ветку (при подготовке master, не main). Не мержи одноимённые соседние эксперименты.

Выполни engineering/addons/ACCEPTANCE_RU.md: offline tests, сборку/подключение обоих
layout и доступные реальные прогоны Codex/Claude, браузера и heavy. Проверяй установленную
версию каждого инструмента; новые установки/аккаунты/расходы согласуй отдельно.
Неимевшиеся host/runtime проверки — NOT_RUN/BLOCKED, не PASS. Не меняй Product,
Desktop, существующий Role Runner, global config, модели, permissions или secrets.

Проведи независимое read-only ревью текущего diff; исправь подтверждённые регрессии,
повтори проверки. Сохрани короткий отчёт с evidence, границами и решениями по каждому
дополнению. Не обновляй исторические locks/fingerprints ради зелёного статуса.

Сделай commit/push исправлений и отчёта только в рабочую ветку. Перед merge обнови
основную ветку и перепроверь совмещённое состояние в отдельной integration-ветке.
Если нет блокирующих дефектов, применимые CI/review пройдены и владелец разрешил
интеграцию, выполни обычный merge/PR в фактическую default branch и push без force.
NOT_RUN не повышает scope совместимости; при незакрытом обязательном gate остановись.
Итог: SHA, PASS/FAIL/NOT_RUN, ограничения и состояние merge. Без rollout в проекты.
