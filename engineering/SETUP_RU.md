# Рабочая среда разработки самого Playbook

Эта инструкция для автора и проверяющих на VPS. Она не устанавливается
подписчику и не применяется автоматически к создаваемым им приложениям.
Используйте отдельный checkout и непривилегированного пользователя.

Из корня выбранного checkout, на Python 3.11+ (в CI — 3.12):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip check
.venv/bin/python -c "import ai_workflow_harness_lab; import pytest; import jsonschema"
```

В Windows Python окружения находится в `.venv\Scripts\python.exe`.
Не используйте глобальный pip или sudo. Установка зависимостей требует сети
и разрешения на изменение этого локального окружения.

`requirements-dev.txt` устанавливает также локальный companion Harness Lab.
`pytest.ini` задаёт пути для основного процесса; `conftest.py` передаёт пути
дочерним процессам. Одного изменения переменной PYTHONPATH внутри conftest
недостаточно для импорта при сборе тестов основным интерпретатором.

Product helpers остаются Python 3.10+ и не требуют Harness Lab или pytest.
Это не заявление о поддержке настоящего Codex desktop на всех платформах.

## Проверка и происхождение результата

[Протокол VPS](../docs/delivery/VPS_ACCEPTANCE_RU.md) содержит полную очередь
проверок. Начинать нужно с общего pytest и канонического verifier, затем
проверять поставку и целые пользовательские истории. Не исключайте падающие
тесты ради зелёного статуса. Frozen environment pilots проверяются только при
их настоящих prerequisites; обычный VPS не переименовывается в прежнюю среду.

В этой ветке версия test-зависимостей не объявляется полностью зафиксированной:
сохраните Python, pip freeze, ОС, CLI и source SHA вместе с результатом.
Сравнимые model runs должны пользоваться одной замороженной средой. Необязательные
проверки других проектов не запускаются и не обновляются через этот setup.
