# Engineering — рабочая инженерная система

Здесь автор **использует Playbook для создания новых и развития текущих проектов**,
а не только исследует методику. Реальная разработка, использование собственной
системы и R&D — три связанных, но разных режима.

[Как работать](USAGE_RU.md) · [Эксперименты и перенос в продукт](experiments/README.md) ·
[Общие механизмы](../shared/README.md) · [Полный Governed](../docs/governed/README.md).

Рабочие исходники остаются по прежним путям: `tools/`, `prompts/`, `schemas/`,
`templates/`, `PLAYBOOK.md`. Это намеренная совместимость, не недоделанный перенос.
Engineering — полноценный вход к ним. Ни один downstream не мигрирует автоматически.

Для длинных и рискованных проектов доступны Feature Workflow, независимые
проверки и Deep Review, AI/RAG eval, cost controls, continuity и recovery.
Подключайте их по контракту проекта и реальному риску, не по бренду модели.
Работающая модель и настройки основного агента остаются настройками его среды.

Экспериментальная ветка не является новой рабочей версией. Перед использованием
нового механизма: область изменений, закреплённая версия, проверки, ограничения,
откат. Технически успешный эксперимент не доказывает пользовательскую пользу.
