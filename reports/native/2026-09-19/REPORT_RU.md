# Playbook Native: старт, испытания и основания решений

> Исторический отчёт. Подробные материалы сохранены в [неизменяемом архиве](../README.md); ссылки ниже ведут на проверенный коммит.

Дата: 19.09.2026. Исходная версия: `f650301` / `0.1.0-preview.1`.
Текущий кандидат: `0.1.0-preview.2`. Только синтетические repos; master и downstream
не изменялись. Это диагностика продукта, не benchmark и не готовый публичный релиз.

## Что получилось

[Открыть стартовую страницу](../../../docs/native/start.html). Она работает локально,
без зависимостей: описать задачу → при желании изменить настройки → скопировать
запрос в Codex. Три карточки помогают начать. Пользователь может сразу написать
`$playbook` и задачу, не открывая страницу.

Агент определяет три независимых измерения: новый/существующий проект,
создать/исправить/проверить, автоматически/сначала план/расширенный контроль.
Явный выбор пользователя важнее предположения. Быстрый режим сохраняет проверку;
план останавливается до изменений; проверка сама по себе не разрешает исправления.

[Скриншот desktop](https://github.com/ashishki/AI_workflow_playbook/blob/b80eb56aebef97615724995dacc6b6512edbd15b/reports/native/2026-09-19/start-1280.png) · [Скриншот телефона](https://github.com/ashishki/AI_workflow_playbook/blob/b80eb56aebef97615724995dacc6b6512edbd15b/reports/native/2026-09-19/start-390.png).

Страница составляет запрос, а не запускает агента и не определяет содержимое
репозитория. Это сознательное ограничение: используем уже открытый проект и
возможности Codex, не строим второй агентный клиент.

## Как проверяли

[Протокол](../../../evals/native/PROTOCOL.md) задан до первых запусков; изменения
после наблюдений отмечены отдельно. [Runner и команды](../../../evals/native/README.md)
воспроизводят испытания через настоящий `codex exec`, не через заготовленные ответы.
Обычный Codex и Native получали одинаковую задачу, исходную форму и возможности.
Native дополнительно получал project block и skills. Подключение в этих задачах
подготавливал evaluator; это не доказательство самостоятельной установки.

Среда: Linux, `codex-cli 0.155.1`, настроенный `gpt-6-astra`, effort `xhigh`, без смены
модели; `workspace-write`, approval `never`. Внешние проверки: имеющийся Playwright
1.61.1 и Chromium. Дополнительная MCP-пара использовала официальный Playwright MCP
0.0.82 с временной конфигурацией и отдельным localhost-сервером для каждого checkout.
Глобальные настройки не менялись. Профиль host не был чистым; его общие инструкции
могли влиять на оба условия. Денежная стоимость неизвестна; usage записан как
сообщён CLI, без предположений о биллинге.

В исходной форме `npm test` проходит, но успешная отправка падает и мобильная
форма выходит за экран. Независимый browser probe действительно нашёл эти ошибки:
4 из 8 проверок не прошли. Это полезная защита от теста, который всегда зелёный.

## Наблюдения

| Испытание | Фактический результат | Что это доказывает |
|---|---|---|
| Стартовая страница | 48 сочетаний настроек, карточки, пустой ввод, вызов clipboard API через stub и реальный fallback выделения текста, ввод как текст, 390/1280 px; без ошибок JS и внешних запросов | Работает интерфейс. Это не 48 испытаний понимания задач агентом |
| Codex / Native, обычный frontend | Оба исправили overflow и сломанный submit; внешний Chromium дал 8/8 каждому | Оба результата проходят эти конкретные проверки |
| Codex / Native с локальным MCP | Код исправлен, внешняя проверка 8/8 каждому; агенту навигация отказана | Установка MCP не равна доступу к браузеру |
| Нет доступного agent browser | Во всех четырёх frontend-прогонах ограничение явно названо | В этих попытках нет ложного «UI проверен»; полный цикл не доказан |
| Setup preview.1 | `.agents` защищена; skills не установлены, но блок уже добавлен в override | Найден дефект порядка подключения; честное «частично» не делает onboarding успешным |
| Setup после исправления | При том же запрете все исходные файлы побайтово сохранены; блока нет | Исправлена частичная установка. Полная установка/reconnect не проверены |
| Существующий проект + создать + план | План выдан; исходные файлы не изменены | Соблюдена граница plan-only в этой задаче |
| Новый проект + создать + план | План и существенные вопросы; файлы не созданы | Не начинается реализация без следующего запроса |
| Backend fix | Исправлен только Python helper, checks прошли; frontend skill/browser не загружались | Предметный skill не навязан этой backend-задаче |
| Проверить + расширенный контроль, первая попытка | Исходники сохранены, дефекты найдены, итог не выдан за 300 секунд | Незавершённый trial; потребовалось сузить процесс |
| Проверить + расширенный контроль, повтор | За 248.63 с выдан итог с дефектами и ограничениями; исходники сохранены, только временный тест/протокол | Новый вариант завершил этот случай; независимого reviewer и browser verification нет |
| Быстрый режим через `$playbook` | Код исправлен, meaningful regression tests выполнены, служебные документы не созданы; внешний браузер 8/8 | Быстрый режим сохранил проверки и честное ограничение доступа к browser |

Всего **12 настоящих запусков Codex: 11 завершённых ответов и 1 timeout**.
Это не «11 успешных задач»: завершённый ответ может честно сообщать blocker.
Все неудачи сохранены в [машиночитаемых записях](https://github.com/ashishki/AI_workflow_playbook/blob/b80eb56aebef97615724995dacc6b6512edbd15b/reports/native/2026-09-19/results.json).
Каждая запись содержит фактический prompt, исходную версию и hashes, итог,
изменения, usage и fingerprints локальных логов. Raw events остаются в ignored
`.playbook-artifacts/native-pilot/`; сохранённые записи не заменяют полные логи.

Внешний evaluator открывал **итоговые** файлы приложения, взаимодействовал с формой,
проверял подтверждение, ошибку email, горизонтальное переполнение и видимость
кнопки на 390/1280 px, Tab до кнопки и ошибки страницы. Скриншоты обычной пары
просмотрены; мобильный и широкий итог сохранили оформление и читаемую форму.
Это не полная accessibility-проверка, не проверка настоящей рассылки/backend
и не доказательство визуальной пригодности других сайтов.

## Что изменили именно по результатам

| Основание | Решение | Что пока остаётся предположением |
|---|---|---|
| Пользователь выбирает три независимых измерения; карточки не покрывают все задачи | Один `$playbook`, необязательные карточки, ручная коррекция любого измерения | Новичкам действительно проще — нужен usability-пилот |
| Базовый Codex тоже справился с формой | Сохраняем тонкий пакет; не добавляем роли и не обещаем рост качества/скорости | Польза frontend skill на новых задачах ещё не доказана |
| Защищённая `.agents` оставляла половину подключения | Сначала доступность skills, потом проектный блок; при отказе прежние файлы целы | Штатная установка plugin и полный lifecycle ещё не подтверждены |
| Browser/MCP недоступен самому агенту | Проверка capability до обещаний; отказ остаётся ограничением; MCP опционален | Удобство конкретного browser channel надо проверить на поддержанном host |
| Расширенная проверка ушла в подготовку файлов и не закончилась | Замечания в ответе по умолчанию, проверка по задаче, точная ссылка на browser reference | Нельзя приписать эффект только тексту: retry имеет больший deadline |
| Harness мог считать повреждённый event stream успешным | Nonzero exit при parse errors; unit test с явно fake CLI | Эти unit tests не оценивают модель |

Нет оснований рекламировать статистическое преимущество: одна задача, один host,
нечистый профиль, фиксированный порядок, вмешательство между версиями. Повторные
попытки — разработка на обнаруженных случаях, не независимая контрольная выборка.
Не сравниваем задержки при разных deadlines и не складываем blocked-пары в победы.

## Проверка изменений репозитория

- Plugin manifest и оба skills проходят штатные validators; Python/JS scripts
  проходят синтаксическую проверку.
- Пять unit tests eval runner прошли: сохранение существующих evidence, timeout,
  нулевой exit без завершения, повреждённый stream, сбор корректного результата.
  Это harness tests с fake CLI, отдельно от 12 настоящих запусков модели.
- Повторный полный pytest: **222 passed, 12 skipped, 2 failed**. Обе ошибки прежние:
  frozen pilot asset manifest и версия toolchain исторического pilot. Они были
  воспроизведены на `d070f4e` ещё при предыдущей ревизии; historical evidence не
  переписывали ради зелёного отчёта. [Подробности](../../../docs/handoffs/CODEX_FRONTEND_SKILLS_MCP_HANDOFF.md).
- `integrity_check` прошёл с двумя прежними предупреждениями об отсутствующем
  generated cognition content. UI стартовой страницы повторно проверен после правок. 112 локальных ссылок
  разрешаются; diff проходит whitespace check.

## Что нужно до раздачи подписчикам

1. Подтвердить нормальную установку plugin, discovery в новой сессии,
   connect/reconnect/update/remove на объявленном host. Изолированный незарегистрированный
   marketplace не обнаружился автоматически; global config ради теста не меняли.
2. Завершить agent/browser цикл в среде, где агенту разрешены навигация и просмотр
   изображений. В текущем CLI навигация требовала approval, недоступного при `never`.
   Отдельный успешный запуск самого MCP этого ограничения не снимает.
3. Испытать новые задачи: новый экран, другой web stack, устаревший/чужой preview,
   смена режима пользователем по ходу. Сравнивать равные возможности, сохранять неудачи.
4. Решить права на использование пакета, затем провести небольшой пилот с новичками
   и подготовить versioned artifact. Контакты с подписчиками и публикация не выполнялись.

Это технические критерии выпуска и одно решение владельца о правах, а не повод
возвращать CF-00–CF-09 и обязательные approval для обычной работы.

Основания упаковки: [OpenAI Skills](https://developers.openai.com/codex/skills/),
[официальная инструкция plugins](https://learn.chatgpt.com/docs/build-plugins#create-a-skills-only-plugin-manually),
[Codex noninteractive](https://developers.openai.com/codex/noninteractive).
Документация подтверждает механизм; наблюдения выше — его фактические пределы
в нашем окружении. [Продуктовая модель](../../../docs/research/CODEX_FRONTEND_SKILLS_MCP_ADOPTION_RU.md)
содержит остальные первичные источники и принятые архитектурные решения.
