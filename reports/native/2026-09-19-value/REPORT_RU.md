## Что изменили и на каком основании

Пользователь справедливо поставил вопрос: зачем открывать HTML и переносить
запрос, если можно сразу написать агенту. Поэтому основной маршрут теперь
«открыть подготовленную папку в Codex → описать задачу». START — необязательная
помощь; конструктор и карточки свёрнуты по умолчанию. Все три измерения процесса
сохраняются и меняются в чате. Это решение по прямой обратной связи, а не результат
ещё не проведённого usability-пилота.

Основной skill и блок проекта сокращены с 8 094 до 3 683 байт, со 131 до 61 строки.
Удалены повторения общих обязанностей агента; сохранены plan/check boundaries,
проверка реального результата, frontend и автоматический Role Runner. В блоке
теперь явная ссылка на entry skill. Поэтому это сравнение двух вариантов пакета,
а не изолированный опыт «меняется только длина текста». Статический размер
уменьшился на 54,5%; это **не измеренная экономия токенов**.

README, модель и план продукта переписаны вокруг прямого входа и проверяемой
пользы. База продуктового сравнения — обычный агент; предыдущая версия нужна
дополнительно для регрессий. Наличие reviewer, skill или зелёного CI не называется
конкурентным преимуществом. Новых runtime, MCP, лаборатории и управляющих форм нет.

## Условия опыта

Существующий Harness Lab, `run`, `verify-bundle`, `compare`, тот же command adapter.
Две новые задачи: сохранность бронирований и экспорт только разрешённых контактов.
Правила находятся в README проекта, одинаковом для всех вариантов. Внешний
оценщик находится за пределами редактируемой fixture. Его проверки сначала
провалили исходные ошибки и четыре мутанта и прошли на контрольных реализациях.
Это проверка перечисленных случаев, не доказательство полноты оценщика.

Три условия: plain без проектного Playbook; current preview.5; lean preview.6.
Две попытки каждого условия в каждой задаче, чередующийся порядок, до 12 запусков
по 240 секунд. `gpt-6-astra`, effort `xhigh`, CLI 0.155.1, workspace-write,
approval never. Модель/effort указаны по конфигурации host; Lab хранит заявление оператора.
Модель и глобальные настройки не менялись. Общие инструкции host
сохранены; это не чистый аккаунт новичка. Claude Code не участвовал.

Всем явно сообщено, что независимый reviewer недоступен и запускать его нельзя:
вложенный CLI уже блокировался этой средой. Сравниваем **только инструкции без
ревью**, не весь продукт и не полезность Role Runner. В продукте автоматическое
ревью сохранено по решению автора. Эти задачи не требуют браузера.

Исходники Lab, adapter, suite, prompts, fixtures, оценщик и варианты пакета
зафиксированы хешами перед batch. Неудачи не заменяются удачными попытками.
Raw-данные: `.playbook-artifacts/native-value-20260919/`; источник пакета current
сохранён из Git, lean заморожен отдельно. README пакета впоследствии обновлён
для пользовательского входа, но исполняемый код, skills и project block кандидата
соответствуют замороженному варианту. Обе технические копии не являются разными
поведенческими версиями. Полный журнал пока локален; независимый читатель не может
считать этот путь опубликованным доказательством.

## Результаты model trials

**Ошибка подготовки опыта:** у lean в шаблоне команды другой путь `--package`.
Поэтому его compatibility fingerprint отличается; Lab не принимает пары с lean
как формально сопоставимые. У plain/current шаблон одинаковый. При ручной сверке
команд различается только ожидаемый путь к варианту пакета, однако это не повод
переписывать сохранённые fingerprints или отключать проверку. Числа lean ниже —
описательная диагностика, не прошедший автоматический gate A/B-результат.
Для следующего опыта в протокол добавлен fake-CLI preflight всей пары и одинаковый
шаблон; новый regression test подтверждает, что разница команд отклоняется.

По экспорту контактов завершились все шесть запусков; все прошли семь исходных
групп внешних проверок. Ни один вариант не получил помощи после запроса.
Медианы двух завершённых запусков на условие:

| Вариант | Input tokens (включают cached) | Cached input | Output tokens | Вызовы инструментов | Секунды |
|---|---:|---:|---:|---:|---:|
| Обычный Codex | 180 514 | 151 296 | 6 237 | 5 | 140,0 |
| Preview.5 | 257 460,5 | 214 144 | 9 020,5 | 7,5 | 192,1 |
| Сокращённый preview.6 | 213 593,5 | 182 272 | 7 494 | 5,5 | 159,7 |

На этом случае сокращённый пакет требует меньше учтённых токенов и времени,
чем прежний. Обычный Codex имеет лучшие значения этих счётчиков при том же
проверенном результате. Это две попытки одного случая, не общий процент экономии.
Cached input не прибавляется к input повторно; output включает reasoning.
Денежная стоимость неизвестна, влияние кеша и нагрузки не изолировано.

Шесть финальных ответов экспорта прочитаны вместе с trace: все дают команду для
получения CSV; выполненные тесты и фактическая проба выгрузки видны в журналах.
Утверждений о запуске недоступного reviewer нет. Наличие технической команды
ещё не доказывает, что новичок сможет самостоятельно ею воспользоваться.

По бронированию все шесть файлов результата прошли восемь исходных групп
проверок. Четыре запуска не завершили работу до лимита 240 секунд; их usage
неполон и остаётся `unknown`. Повторный plain завершился за 228,6 секунды,
повторный lean — за 193,8; current оба раза достиг лимита. Эти два завершённых
ответа также прочитаны: проверки и сохранность подтверждены, ограничение на
параллельные записи названо. Это локальный модуль, не работающий сайт записи.

**Всего 12 попыток, 8 завершены, 4 таймаута.** Код с проходящими внешними
проверками не превращает прерванный запуск в завершённую задачу. Все 12 bundles
прошли `verify-bundle`; все 49 замороженных файлов совпали после batch. Ни одного
независимого reviewer не запускалось. Стоимость полного набора неизвестна;
прерванные tool traces нельзя сравнивать как полную стоимость успешной задачи.

Все три `compare` вернули ненулевой код при `--fail-on-invalid-run`.
У plain/current нет ошибок совместимости; у двух пар с lean — по четыре ошибки
fingerprint. Таким образом, формальный gate всего опыта **не пройден**. Его
нельзя представить успешным по строке `status: empirical comparison` или
агрегатной метрике false-success: последняя не оценивает свободный текст ответа.

## Дополнительная проверка после batch

При чтении оценщика обнаружили пробел: он проверял API и символические ссылки,
но не публичную CLI-команду и жёсткую ссылку на исходник. Основной опыт не меняли.
После фиксации результатов в suite 3.1.0 / `native.contacts.v2` добавили эти две
группы и два теста с намеренно сломанными реализациями. Контрольный код также
дополнен CLI и защитой hard link; старый контроль был достаточен только для
прежних семи групп. Исходные fixtures, budgets и model traces не переписывались.

Все шесть результатов экспорта скопированы в отдельные каталоги и прошли девять
расширенных групп. Это post-hoc replay готового кода без нового обращения к модели,
не дополнительные model trials и не замена первоначальных оценок. Расширенный
оценщик остался в существующем Harness Lab; ещё один runner не добавлен.

## Решение

- **Прямой вход принят.** Он убирает наблюдённый лишний перенос между HTML и чатом;
  понятность новичку ещё проверяется отдельно.
- **Компактный skill оставлен только экспериментальным кандидатом.** Во всех
  четырёх его outputs новых подтверждённых дефектов нет, текст существенно меньше.
  Но строгий A/B gate и проверка полных затрат не пройдены. Это ограниченное
  основание для дальнейшего испытания, не доказательство отсутствия регрессий.
- **Преимущество над обычным Codex не установлено.** В сопоставимой паре на
  экспорте прежний пакет увеличивал затраты без улучшения проверенного результата.
  Наблюдения lean этого вывода не меняют; они требуют корректно подготовленной пары.
- **Автоматический Role Runner сохранён по решению автора.** Этот опыт намеренно
  исключал reviewer и не проверяет его вклад. Не переносим прежние результаты
  оптимизации Role Runner на эффективность всего Native.
- **Следующий опыт проще:** plain против одного кандидата, предварительный
  fake-CLI `compare`, свежие задачи, доступный полный цикл проверки. Не тратим
  дополнительные попытки сверх 12 ради исправления статистики этого batch.

## Границы и дальнейшее решение

Два локальных Python-сценария не измеряют frontend, установку, все режимы,
полный цикл reviewer или самостоятельность новичка. Human corrections равны
нулю по устройству опыта; это не наблюдение, что помощь человеку не нужна.
Прошедшие внешние проверки не доказывают готовность к произвольной нагрузке.

Следующий продуктовый шаг выбираем по оставшейся неопределённости: полный цикл
с доступным reviewer/browser на свежих задачах и наблюдение первого desktop
запуска. Не придумываем новый слой процесса для объяснения отсутствия эффекта.
Права использования и публичную раздачу решает владелец. Master, downstream,
глобальные настройки и учётные данные не менялись; подписчикам никто не писал.
