2026-09-19. База — `eedeaf3f90f8e440dafb8734264166b61bd3040e`.
Изменения runtime и CI — `63e2494`; одинаковый ZIP для трёх ОС — `1cf494a`.

## Что решили и почему

По решению автора **Role Runner включён автоматически после изменений кода**,
включая быструю правку. Использован существующий движок: Native передаёт короткий
запрос, не требует Git, feature/slice registry или старого prompt renderer.
Одна подходящая роль проверяет результат; основной агент исправляет подтверждённые
проблемы и повторяет нужные проверки. Plan-only сохраняет запрет записи.
Ревьюер не запускает других ревьюеров. Недоступная проверка остаётся недоступной.

Сохранили одну стартовую страницу и два skills. В комплект добавлены только два
Python-файла существующего Role Runner и короткая инструкция. Сборщик проверяет
их совпадение с canonical `tools/`. Не создавали новый оркестратор, лабораторию,
обязательный MCP, набор из четырёх ревью или реестры для новичка.

Прежние [два набора сравнения Role Runner](../../../docs/evaluation/CODEX_ROLE_HARNESS_AB_PILOT.md)
уже проведены и импортированы в Harness Lab: high — input −33,6%, output −16,2%,
время −15,6%; supplementary medium — input −26,9%, output −13,7%, время +186,1%.
Это разные условия одного механизма; проценты не складываются. Новое сравнение
добавляет ревью к Native, где его раньше не было, и не обязано уменьшать затраты.
Здесь мы проверяем интеграцию и границы поведения, а не переносим старые проценты.

## Windows, macOS и Linux

[Первый CI](https://github.com/ashishki/AI_workflow_playbook/actions/runs/35448733026)
прошёл на трёх системах, но обнаружилось различие Windows ZIP: перевод строк и
platform metadata. Добавили точечные `.gitattributes` и фиксированный ZIP platform.
[Повторный CI](https://github.com/ashishki/AI_workflow_playbook/actions/runs/35448960785)
прошёл полностью; хеш и размер архива одинаковы на всех трёх ОС и локально.

На каждой ОС: 11 package/runtime tests с **fake CLI**, сборка, извлечение
фактического ZIP и START в Chromium. Проверены кириллица и пробелы в путях,
неполный/повреждённый trace, таймаут, изменение файлов ревьюером, устаревший
результат и запрет перезаписи журналов. На START проверены 48 сочетаний,
карточки, ввод, clipboard stub и fallback выделения, 390/1280 px, отсутствие
page errors и сетевых запросов. Локальные скриншоты просмотрены.

Это подтверждает переносимость комплекта и его механизмов. Авторизованный
Codex desktop и реальный буфер обмена с новичком на трёх ОС ещё не проверены.
Для Role Runner в среде агента нужны Python 3.10+ и авторизованный Codex CLI;
вход в desktop не доказывает наличие и доступность CLI.

## Реальные испытания через существующий Harness Lab

Условия: Linux, Codex CLI 0.155.1, текущие настройки `gpt-6-astra/xhigh`,
`workspace-write`, approval `never`, одноразовые fixtures. Модель и разрешения
не менялись. Suite расширен до backend, plan, review, frontend. База — preview.4,
candidate — замороженная копия preview.5. По одной попытке на задачу и условие,
с чередованием порядка, максимум 600 секунд на основной запуск. Это диагностика,
не независимый holdout и не достаточное сравнение общей эффективности.

Первый отдельный backend-прогон показал два факта: агент сам вызвал Role Runner,
но вложенный Codex не смог открыть служебное состояние (`Read-only file system`).
Затем агент перенёс неудачный журнал из проекта, из-за чего измеритель посчитал
ноль ревью. Исходный bundle сохранён без исправлений. Добавили требование сохранять
неудачные журналы и выявление вызова без trace: тогда полная сумма затрат `unknown`.
После этого заморозили отдельный диагностический batch; прежнюю попытку не включали
в его парные результаты.

Отдельно настоящий Role Runner запущен из доступной внешней среды на исходной
ошибочной функции, без Git. Получен валидный `STOP_SHIP`: найдены дефисы по краям
и неверный результат для строки из пробелов. Файлы не изменены; повторный `verify`
прошёл. Это проверка движка, а не обход отказа вложенного запуска и не доказательство
полного автоматического цикла внутри текущего eval-host.

Все **8 bundles** прошли `verify-bundle`; 7 основных исполнений валидны, одно
невалидно. Это целостность свидетельств, не успешность всего процесса.
`compare --require-empirical --fail-on-invalid-run --fail-on-hard-gate` вернул **1**
из-за невалидного запуска. Четыре candidate-сценария проходят свои внешние критерии,
но полный frontend browser/review loop внутри агента не подтверждён.
В обеих задачах с изменением кода candidate вызвал Role Runner автоматически;
оба вызова остановились до ревью из-за доступа к служебному состоянию Codex.
Вторых попыток обойти отказ не было; журналы остались в проекте.

Внешний Chromium проверил отправку, неверный email, клавиатуру и layout на
390/1280 px. Скриншоты candidate просмотрены: форма помещается, оформление сохранено.
Исходная fixture тем же probe проваливает успешную отправку, мобильную ширину и
проверку page errors. Браузер оценщика имеет свою разрешённую среду; его результат
не приписывается агенту, которому браузер недоступен.

По backend известен только input основного агента: 104 080 → 208 300; добавленная
проверка не дала экономии. Полная стоимость candidate неизвестна из-за отсутствия
usage у неудачного ревью. В планировании полные input/output — 82 140/1129 →
83 397/1337, в проверке — 85 372/2725 → 69 171/2190. Сумма всего batch неизвестна
в обеих версиях: baseline имеет таймаут, candidate — неполные reviewer counters.
Не считаем неизвестные затраты нулём и не выводим общий процент улучшения.

До завершения batch хеши замороженных источников Lab, adapter, suite и acceptance
совпадали с объявленными. Финальный пакет отличается от trial-копии только README
и уточнением `.gitignore` в connection reference; runtime/review instructions те же.
После batch исправлены ещё два дефекта отчётности: Markdown теперь явно показывает
число невалидных запусков и знаменатель success rate; timeout основного Codex
учитывается, даже если внешний command adapter завершился обычным nonzero exit.
Недоступный Node/повреждённый Playwright также классифицируется как отказ проверяющего,
а не ошибка модели. Эти правки проверены отдельно; исходные bundles и первый
comparison не редактировались. Повторное чтение тех же bundles сохранено отдельно.

## Инженерные проверки

- Plugin и оба skills: валидаторы прошли; две runtime-копии совпадают с исходниками.
- Native: 13 tests PASS, включая 8 Lab integration tests с fake CLI. Проверки ловят
  изменения в plan/review-only, неисправленную функцию, missing/broken browser,
  повреждение/обрыв/таймаут выполнения и корректно учитывают последний в сравнении.
- После последних исправлений все 50 tests существующей Harness Lab прошли.
- Полный pytest: **226 passed, 12 skipped, 2 прежние ошибки**, 122,80 с.
  Затем отдельно прошёл добавленный тест классификации недоступного проверяющего.
- Две ошибки относятся к старому frozen asset manifest и версии Codex CLI
  замороженного пилота. Исторические данные не переписывались ради зелёного теста.
- `integrity_check`: PASS, два прежних предупреждения generated cognition.
- Общий verifier выполнен системным Python: 24/26; pytest там не собрался из-за
  отсутствующих dev-зависимостей. Поэтому полный pytest отдельно выполнен через
  `.venv`, с результатом выше. Общий validator через `.venv` также нашёл шесть
  прежних ссылок из `docs/tasks.md` на отсутствующие записи старого пилота.
  Эти пути отсутствуют уже в базе `eedeaf3`; task-файл не изменён.
  Репозиторий целиком не объявляется зелёным.
