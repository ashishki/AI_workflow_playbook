# Текущая запись проекта: локальное демо записей

Владелец сценария — сопровождающий эксперимента Delivery. Все ученики вымышлены.
Назначение: два преподавателя (Анна/anna и Борис/boris) создают и видят только свои
записи в локальном веб-приложении. Авторитетные требования — неизменённый TASK.md.
notes.txt и установленный .agents сохранены. Это технический синтетический пример;
польза для реального пользователя, живой пилот и передача новому агенту ещё не наблюдались.

## Запуск и проверка

Нужны Python 3.10+ и Linux/macOS с модулем fcntl; сторонних библиотек нет.
Из каталога проекта:

```sh
python3 app.py serve --port 8765
python3 -m unittest -v test_app
```

Открыть http://127.0.0.1:8765. Сервер всегда слушает 127.0.0.1, даже если команда
запускается на VPS. Для остановки — Ctrl+C в терминале процесса. Второй процесс с
тем же JSON не запускается: файл .lock удерживается всё время работы. Не удалять
этот файл для обхода блокировки. Для другого порта есть --port, для другой копии
данных — --data /absolute/path/bookings.json.

## Правила и API

- Выбор преподавателя — демонстрационная идентификация, не пароль и не вход.
  Любой пользователь локального демо может выбрать любую личность. Внедрение в
  реальную среду требует отдельного решения об аутентификации и защите доступа.
- API принимает ровно один заголовок X-Teacher: anna либо boris. Отсутствующий или
  неизвестный заголовок даёт 403. Поле teacher в POST игнорируется: владелец определяется
  только заголовком. Чужой и несуществующий id одинаково дают 404 без имени ученика.
- GET /api/bookings возвращает {"bookings": [...]}; GET /api/bookings/{id}
  возвращает {"booking": {...}}. POST /api/bookings принимает student, date, slot,
  request_id. Успешное создание: 201; повтор request_id: 200 с replayed: true;
  другое обращение на занятое время: 409; неверный JSON/поля: 400.
- student: непустая строка до 100 символов, request_id: до 128 символов. Края
  строк обрезаются. date: реальная YYYY-MM-DD; slot: HH:MM от 00:00 до 23:59.
  Прошлые даты разрешены; часовой пояс — местное время сценария, преобразований нет.
- Уникальность: (teacher, date, slot). Один слот разных преподавателей допустим.
  request_id также изолирован по преподавателю. Повтор валидного запроса с прежним
  request_id возвращает исходную запись даже при изменённых полях; это не редактирование.
  После неопределённого сетевого результата повторять тот же request_id. UI хранит
  ожидающий id в sessionStorage для тех же данных, в том числе после обновления вкладки.
- Запросы сериализованы RLock, сохранение — временный файл, fsync, os.replace,
  fsync каталога. Ошибка сохранения даёт 503. Не следует обещать защиту от отказа
  оборудования/файловой системы сверх этих мер.

Пример локального запроса (только синтетические данные):

```sh
curl -i http://127.0.0.1:8765/api/bookings -H 'X-Teacher: anna' -H 'Content-Type: application/json' --data '{"student":"Вымышленная Маша","date":"2026-10-20","slot":"10:30","request_id":"manual-example-1"}'
curl http://127.0.0.1:8765/api/bookings -H 'X-Teacher: anna'
```

## Данные, восстановление, завершение

Данные по умолчанию: data/bookings.json (создаётся при первом запуске), версия
формата 1. Содержит id, teacher, student, date, slot, request_id, created_at. Внутренние
резервные копии/export содержат записи обоих преподавателей и предназначены только
для владельца синтетического проекта, не являются teacher API. Аккаунтов, ключей,
интеграций, внешних отправок, подписок, расходов API и фоновых расписаний нет.

Перед любым обслуживанием остановить сервер этой копии. Использовать новые пути
для export: существующий экспорт никогда не перезаписывается. Резервный JSON сохраняет
и request_id, поэтому восстановление сохраняет защиту от повторов.

```sh
python3 app.py backup --output backups/bookings-20261009.json
python3 app.py export --output exports/bookings-20261009.json
# Репетиция на отдельной одноразовой копии; рабочую data/bookings.json не затрагивает.
python3 app.py restore --data rehearsal/bookings.json --input backups/bookings-20261009.json
python3 app.py serve --port 8766 --data rehearsal/bookings.json
# После Ctrl+C: сохранить экспорт и перевести только одноразовую копию в off-state.
python3 app.py retire --data rehearsal/bookings.json --output exports/rehearsal-retired.json
# Повторный serve этой копии отклонён; исходный JSON и код сохранены.
python3 app.py resume --data rehearsal/bookings.json
```

При restore сначала проверяется полный JSON, затем предыдущие байты данных
сохраняются рядом в *.before-restore-<id>.json. Новые данные заменяются атомарно.
Изменения после выбранной резервной точки потеряются в восстановленной копии:
сохранённый checkpoint позволяет их сравнить. Для реального восстановления
отдельно выбрать актуальную резервную точку и проверить записи через API после запуска.
retire касается только локальной копии: экспорт + маркер *.retired блокируют запуск.
Это не отмена внешних подписок; их в данном проекте нет. Удаление данных не выполняется.

## Продолжение в новой сессии

Начать с AGENTS.md, TASK.md, этого файла и FINAL_JOURNEY.md. app.py содержит правила,
web/ — UI, test_app.py — проверяемые примеры, .playbook-artifacts/ — фактические журналы.
Запустить проверки и приложение с отдельным --data; не принимать чужой отчёт как
доказательство текущей версии. Следующее ограниченное изменение может быть, например,
проверкой разрешённых слотов, если владелец даст конкретное новое правило. Не придумывать
ответ владельца и не менять TASK.md. Обновить проверку поведения и эту текущую запись.
Границы следующих этапов: отдельная браузерная проверка mobile/desktop, независимое
read-only review и реально новая сессия передачи выполняются ведущим агентом позже.
