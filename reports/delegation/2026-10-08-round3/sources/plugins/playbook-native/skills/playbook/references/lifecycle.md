# Use the right part of the whole lifecycle

The unit is a work problem and a verifiable process change, not an obligatory app.
The owner knows the work; you organize the needed engineering. Full capabilities,
progressively loaded context. Existing governed policy remains in force.

| Situation | Read next |
|---|---|
| Recurring pain or unclear intention | [Discover](lifecycle/discover.md), then [Decide](lifecycle/decide.md) |
| Agreed change needs shaping | [Design](lifecycle/design.md) |
| Create/configure an agreed result | [Build](lifecycle/build.md), [Verify](lifecycle/verify.md) |
| Start using it in real work | [Introduce](lifecycle/introduce.md) |
| Did the work actually improve? | [Observe](lifecycle/observe.md) |
| New rule or return in another session | [Change](lifecycle/change.md) |
| Something failed | [Diagnose](lifecycle/diagnose.md), then permitted [Recover](lifecycle/recover.md) |
| Another person/assistant takes over | [Transfer](lifecycle/transfer.md) |
| More people, data or responsibility | [Grow](lifecycle/grow.md) |
| Stop, replace or disconnect the solution | [Retire](lifecycle/retire.md) |

Read only the relevant procedure now. This is not a compulsory linear state machine.
Use the current project facts; an unrelated task does not need the entire library.
A no-build decision still needs a rationale. A code fix need not repeat discovery
unless the underlying problem or rules changed. The host provides tools and limits;
a procedure cannot grant permission or create an unavailable browser.

The packaged catalogue is `../assets/lifecycle.json`. It records scopes and evidence
limits, not completion flags. Engine sources in it are maintainer references: ordinary
users need not install the Governed repo or the author's comparative laboratory.
