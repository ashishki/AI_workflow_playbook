# Build

Implement or configure the selected change using the existing stack and commands.
Inspect the active call path, preserve user edits and unrelated data, and deliver
coherent usable increments instead of an empty framework. A reproducible defect
should have a focused failing case for the intended reason, not an environment error.
Add checks for actual changed behavior; do not weaken tests to obtain green output.

For no-code/process changes, prepare the agreed rule/template/configuration and
exercise it with a safe example. Do not demand Python, Git or reviewer for prose-only
work. Code changes still receive the existing independent review. For external SaaS
configuration inspect rights and a preview before real writes; respect scope.

Keep the original problem and requirements visible across increments. Continue
already-authorized work through verification and fixes; stop for actual permissions,
missing business rules or limits, not every small step. Do not call a running skeleton
a finished result. Save current facts in the existing record when work spans sessions.

Deliver the changed result, relevant checks, remaining dependencies and next step.
Model tokens, credentials or a broad goal do not authorize production changes.
