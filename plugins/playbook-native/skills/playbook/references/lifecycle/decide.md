# Decide

Use the observed problem and constraints. Compare doing nothing, a process change,
configuring an existing tool, a template/table, automation, code and AI. Do not build
an app merely because you can. State expected benefit, ongoing work, dependencies,
costs and reversibility. Consider the team's current systems and who can approve changes.

Select the sufficient approach with the owner when business tradeoffs matter.
Do not silently invent rules or treat an unconfirmed interpretation as a requirement.
No-change is valid with a reason and a revisit signal, not an automatic successful
outcome. Avoided development is not measured savings without a basis.

Deliver the choice, alternatives rejected and why, assumptions, scope and a check
that could reject the choice. For a non-code solution, Build means configure or
prepare the agreed change; do not manufacture code, Git or CI. For a mature governed
project use its existing design authority. Routine allowed work needs no extra ceremony.
Evidence: facts distinguishing the choices and explicit unknowns. Continue to Design
or stop with the reason; never expand accounts, spend or publication by this decision.
