# Recover

Recover only with applicable authority and a known target state. Separate code/UI
rollback, schema migration, data restore and compensation of external actions. Git
revert does not unsend email or restore deleted records. A file hash is not a backup.

Preserve the damaged state for permitted diagnosis, choose a verified backup/checkpoint,
rehearse restore on disposable data and explain potential loss. For unknown provider
outcomes reconcile actual receipts before retry/compensation. Never copy authentication
or weaken sandbox permissions to bypass failure. Do not invent a recovery point.

Execute only approved operations, verify restored content and the real user path,
check queued/repeated actions and document remaining divergence. No backup or authority
means an explicit blocker and safe fallback, not a fabricated successful restore.

Deliver what was restored, from which point, what could not be recovered, residual
risk and the next prevention/change step. Evidence is observed restored data/behavior;
an instruction or successful command alone does not prove business recovery.
