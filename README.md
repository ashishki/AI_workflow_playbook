# Playbook для Codex

Небольшой пакет проектных инструкций, skills и независимого ревью. Вы открываете
проект в Codex и описываете задачу обычными словами. Playbook задаёт ожидания к
границам работы, проверке результата и понятному итогу.

**Статус: `0.1.0-preview.6`, экспериментальный комплект.** Мы проверяем, даёт ли
он пользу сверх обычного Codex. Работающая упаковка и наличие reviewer сами по
себе этого не доказывают. Доступ к Codex нужен отдельно; совместимость нашего
пакета с Claude Code пока не заявлена.

## Начать работу

1. Распакуйте комплект Playbook.
2. Откройте в Codex папку **«Мой проект»** из комплекта — инструкции уже внутри.
3. Напишите задачу. Например: «Сделай учебный сайт преподавателя. Пока без оплаты
   и отправки заявок. Проверь его и покажи, как открыть. Я не программист».

Можно сразу писать в чате. **START.html необязателен**: это помощь с первым
запуском, примеры и конструктор запроса для тех, кому он полезен. Переносить текст
через отдельную страницу для каждой задачи не нужно. Завтра откройте тот же проект
и опишите следующее изменение.

[Первый запуск и свой проект](docs/native/QUICKSTART_RU.md) ·
[Необязательная помощь](docs/native/start.html) ·
[Сборка комплекта для автора](distribution/native/README.md).
Публичного выпуска и ссылки для общей раздачи пока нет.

## Что входит

Два skills: единый вход и работа с интерфейсом. Короткий блок в проекте.
Существующий Role Runner для автоматического независимого ревью изменений кода,
включая быстрые задачи. Он требует Python 3.10+ и авторизованный Codex CLI в среде
агента; при отказе агент сообщает, что ревью не состоялось. Обязательного MCP нет.

Обычно агент определяет подход сам. Управлять им можно прямо в разговоре:

| Выбор | Что написать |
|---|---|
| Новый или существующий проект | «Начни новый проект» / «Измени этот проект» |
| Создать, исправить или проверить | Описать результат / ошибку / попросить только найти проблемы |
| Автоматически, сначала план, расширенный контроль | «Сделай и проверь» / «Сначала план, файлы не меняй» / «Особенно тщательно проверь ошибки и сохранность данных» |

Быстрая работа сохраняет проверку. Проверка без исправлений сохраняет исходники.
План останавливается до реализации. Эти границы поддерживаются инструкциями;
качество исполнения зависит от агента и доступной среды.

## Что проверяем как продукт

Критерий пользы — меньше оставшихся дефектов и ручного управления при разумных
затратах. Сравниваем обычного агента, текущий пакет и сокращённый вариант на
одинаковых задачах. Не обещаем универсального ускорения или улучшения качества.

- [План сравнения с обычным агентом](evals/native/VALUE_CHECK_RU.md).
- [Результаты и ограничения](reports/native/README.md).
- [Windows, macOS, Linux](docs/native/PLATFORMS_RU.md): проверка пакета на трёх ОС
  прошла; самостоятельный desktop-проход новичков ещё нужен.
- [Протокол автора](docs/native/DEVELOPMENT_RU.md): проблема → небольшое изменение
  → проверка → оставить, упростить или убрать. Используем существующий Harness Lab;
  Ground Truth Lab отложен. Лаборатория не устанавливается подписчику.

Исходники пакета — `plugins/playbook-native/`; сборщик — `distribution/native/`;
сценарии — `evals/native/`; лаборатория — `companion/ai_workflow_harness_lab/`.
[Governed-справочник](docs/governed/README.md) сохранён для существующих проектов.
