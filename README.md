# Playbook: задача → проверенный результат

**Playbook помогает работать в Codex.** Вы описываете задачу обычными словами,
агент разбирается в проекте, предлагает подход, делает работу, проверяет результат
и исправляет найденные проблемы. В конце объясняет, что готово и что осталось.

Мы даём небольшой комплект: два skills для Codex, подготовленную папку первого
проекта и понятную стартовую страницу. Код проходит автоматическое независимое ревью
через включённый Role Runner. Для первого запроса не нужны терминал, выбор ролей,
чтение большого руководства или настройка MCP. Доступ к Codex нужен отдельно;
для ревью агент проверяет наличие Python и Codex CLI в своей рабочей среде.

**Статус: `0.1.0-preview.5`, кандидат для разрешённого тестирования.**
Целевые системы — Windows, macOS и Linux. Есть проверки упаковки, CLI-подключения
и работы агента с браузером. [Границы проверки платформ](docs/native/PLATFORMS_RU.md). Самостоятельный
первый запуск новичка через desktop ещё не проверен; публичного выпуска пока нет.

## Как пользоваться

1. Получить пробный комплект, распаковать его и открыть `START.html`.
2. Открыть Codex и выбрать папку **«Мой проект»** из комплекта.
3. Написать: «Playbook, сделай учебный сайт преподавателя. Проверь его на телефоне
   и покажи, как открыть результат. Я не программист».

**Задачу отправляют в чат Codex.** `START.html` объясняет запуск и помогает
составить запрос; сама страница не запускает агента. После первого раза можно
сразу открывать проект в Codex и описывать следующую задачу.

[Первый запуск и подключение своего проекта](docs/native/QUICKSTART_RU.md) ·
[Стартовая страница](docs/native/start.html).
Скачанный репозиторий — исходники для автора; готовый комплект собирается
[этой командой](distribution/native/README.md). Публичной ссылки на выпуск ещё нет.

Обычно агент сам выбирает процесс. При желании его можно изменить:

| Выбор | Возможности |
|---|---|
| Проект | Новый или существующий |
| Задача | Создать, исправить или проверить |
| Участие пользователя | Автоматически, сначала план или расширенный контроль |

Быстрая правка требует меньше обсуждений и документов, но сохраняет проверку.
«Сначала план» останавливает реализацию; «проверить» не разрешает молча исправлять
исходники. Для интерфейса нужны действия в работающем браузере и визуальная
проверка. Если инструмент недоступен, агент должен прямо сказать об ограничении.

## Как автору продолжать разработку

[Короткий протокол развития](docs/native/DEVELOPMENT_RU.md): проблема пользователя
→ минимальное изменение → проверка → решение → новая версия комплекта.
Для испытаний используем **существующий Harness Lab**. Ground Truth Lab — позже.
Лаборатория остаётся у автора и не устанавливается подписчику.

- [Native-проверки в Harness Lab](evals/native/harness/README.md) — исправление
  ошибки, план, проверка без исправлений и интерфейс; учёт токенов основной работы и ревью.
- [Все проверки продукта](evals/native/README.md) — браузер, подключение, упаковка.
- [Что проверено, что не доказано](reports/native/README.md) — короткие результаты
  и доступ к историческим доказательствам.
- [План пробы с новичками](docs/native/PILOT_RU.md) — следующий шаг до выпуска.

Не обещаем, что Playbook уже доказанно быстрее или качественнее обычного Codex.
Проверки механизмов и отдельные успешные задачи этого не устанавливают.

## Где что лежит

| Путь | Назначение |
|---|---|
| `plugins/playbook-native/` | Исходный пакет skills |
| `docs/native/` | Запуск для пользователя и протокол для автора |
| `distribution/native/` | Сборка маленького комплекта |
| `evals/native/` | Случаи и проверки Native |
| `companion/ai_workflow_harness_lab/` | Уже существующая лаборатория |

[Расширенный Governed-справочник](docs/governed/README.md) сохранён для проектов,
которым нужны формальные контракты и контроль. В Native включён его Role Runner; остальные
инструменты, шаблоны и история остаются в расширенном пути. [Полный указатель документации](docs/README.md).
