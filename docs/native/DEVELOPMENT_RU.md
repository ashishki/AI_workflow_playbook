# Развитие Playbook после vNext

[Engineering](../../engineering/README.md) — реальная разработка новых/текущих
проектов плюс отдельно эксперименты. [Product](../../product/README.md) — полный
путь небольшой рабочей проблемы. [Shared](../../shared/README.md) — общие исходники.
Предыдущий протокол сохранён в `../vnext/history/DEVELOPMENT.before-vnext.md`.

Не начинайте с количества skills и переноса папок. Назовите проблему, нужные
стадии, критерий результата, зависимости, права и предел проверки; сделайте
связанный законченный путь; проверьте, исправьте, сохраните фактическое состояние.
Маленькое изменение не требует новой архитектуры. Полный назначенный этап не
сокращается до одной рабочей функции. Действующие Governed-контракты не ослабляются.

В Product после изменений кода — существующий независимый Role Runner; собственные
проверки не заменяют его. Если CLI/browser недоступны, фиксируйте пробел, не меняйте
права и не называйте prompt выполненным review. Никаких рекурсивных reviewers.

Для сравнения используйте **существующий** Harness Lab и Native adapter.
До платных запусков — fake-CLI проверка совместимости пары тем же compare,
одинаковый command template, фиксированные suite/fixtures/версии/модель/права.
Plain — обычный сильный агент, не искусственно ослабленный. Полный продукт и
instruction-only сравнение различаются. Неполный запуск/таймаут не становится
успехом из-за верного промежуточного кода. Unknown usage/цена не равны нулю.
Не менять замороженные fingerprints; не заменять неудачи дополнительными успехами.

Репозиторные проверки: `python -m unittest discover -s tests/vnext -v`,
`python tools/vnext_check.py --root .`, существующие affected Native/package checks,
`python distribution/native/sync_runtime.py --check`. Архив проверять после сборки.
Библиотека не устанавливает пользователю лабораторию или raw traces.

Реальные кейсы проверяют процесс целиком: внедрение, эффект, новое изменение,
передачу и восстановление. Каждая помощь автора — наблюдение, не невидимый вклад.
[Пилот](../../product/pilots/README.md). Не требуется заранее доказывать каждую
строку для проектирования системы; требуется не выдавать гипотезу за установленную
пользу. Готовность кода, live-workflow и самостоятельность — отдельные результаты.

Все обязательства текущей работы и незавершённые внешние проверки — в
[STATUS](../vnext/STATUS.md). Права, реальные данные, подписки и публичный выпуск
остаются отдельными решениями; менять master/downstream автоматически нельзя.
