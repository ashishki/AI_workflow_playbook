# Playbook Native: начать с одной задачи

Playbook помогает агенту подключиться к репозиторию, реализовать изменение,
проверить работающий результат и показать понятный итог.

**Сейчас доступен исходный preview, а не опубликованный installable release.**
Публичная раздача ждёт выбора прав на использование и проверки установки на
реальных hosts. [Текущие права](../LEGAL_STATUS.md) не изменены. Инструкция ниже —
для владельца и разрешённого тестирования кандидата.

## Попробовать текущий кандидат

Понадобятся Codex с доступом к локальным файлам/командам, этот checkout Playbook
и отдельный разрешённый scratch repo. Для UI также нужен browser tool, который
может открыть локальное приложение, и возможность просмотра screenshots.
Наличие подписки/модели само по себе не подтверждает доступность этих инструментов.

1. Откройте Codex в scratch repo. Попросите, подставив абсолютный путь к checkout:

   ```text
   Прочитай /путь/AI_workflow_playbook/plugins/playbook-native/skills/playbook-setup/SKILL.md
   и подключи Playbook Native к текущему репозиторию. Сохрани существующие
   инструкции и мои изменения. Покажи, какие проверки и браузер доступны.
   ```

   Агент прочитает команды проекта, добавит небольшой блок в действующие
   инструкции и скопирует две папки skills, если их ещё не предоставляет plugin.
   Не нужно запускать старый `init_playbook_project.py`.

2. Откройте новую сессию, если инструкции/skills ещё не подхватились. В CLI/IDE
   проверьте наличие `playbook-setup` и `playbook-frontend` через `/skills`.
   Для UI-задачи агент должен подтвердить доступный способ открыть приложение.

3. Поставьте обычную задачу:

   ```text
   Исправь форму подписки: на узком экране кнопка выходит за границы.
   Сохрани оформление сайта. Проверь отправку, ошибку валидации
   и внешний вид в работающем приложении.
   ```

Дальше не нужно выбирать роли или запускать цепочку prompts. Если задача ясна,
агент реализует её, проверит и исправит найденные проблемы. Для нового экрана
полезно дать аудиторию, назначение и референс; заполнять отдельный brief не нужно.

При уже установленном plugin первый шаг короче:
`$playbook-setup Подключи Playbook к этому репозиторию`.
Plugin-directory listing для этого пакета пока не опубликован; не ищите
несуществующую кнопку установки. Repo-local и plugin installation не смешиваются.

## Как выглядит полезный итог

Иллюстрация формата, **не результат реально выполненного trial**:

```text
Кнопка теперь помещается; отправка и сообщение об ошибке работают.
Проверено: проектные tests/build, отправка формы, невалидный email,
клавиатура; экран 390 и 1280 px. Скриншоты: [ссылки на реальные файлы].
Не проверено: Safari — доступен только Chromium.
```

Достаточно знать, что изменилось, что действительно проверено, и что осталось.
Если browser недоступен, корректный итог говорит «UI не проверен» и называет
конкретный способ закончить проверку. Build success не заменяет браузер.

## Если что-то мешает

| Симптом | Следующий шаг |
|---|---|
| Skill не появился | Проверить `.agents/skills` либо установленный plugin и scope; открыть новую сессию |
| Изменён AGENTS, но правило не действует | Проверить `AGENTS.override.md`, nested instructions, repo trust и лимиты host |
| Есть старый Playbook/Superpowers/другая обязательная методология | Выбрать governing workflow; setup не должен отменять его автоматически |
| CLI/IDE не имеет browser | Переиспользовать существующий runner/один подходящий browser tool либо desktop browser |
| Приложение открывается без последних изменений | Запустить свой checkout на свободном порту и проверить характерное изменение |
| Нет доступа к данным/аккаунту | Дать разрешённые fixtures/доступ либо оставить точное ограничение; секреты не отправлять в чат |

Встроенный browser описан для desktop; в Codex CLI/IDE он отсутствует.
Доступность проверяется в текущей среде, а не по названию модели.
[Официальная документация Browser](https://developers.openai.com/codex/browser).

MCP для старта не нужен. Подключайте его, когда конкретной задаче нужен Figma,
DevTools или внешний контекст и существующие инструменты неудобны/недостаточны.
Агент не должен устанавливать весь каталог plugins или менять global config.

## Обновить или убрать

Попросите `$playbook-setup` обновить пакет из выбранной версии или удалить Native
из этого repo. Агент покажет diff, сохранит ваши правки и уберёт только свой блок
и установленные им skills. Для plugin используйте также штатное управление
plugin host. Отключение plugin само по себе не удаляет блок в `AGENTS.md`.

Проектные tests, код и полезные notes остаются вашими. Нет сервера Playbook,
аккаунта Playbook, телеметрии пакета или фонового автозапуска. Сам Codex и отдельно
подключённые tools имеют собственные условия и настройки.
