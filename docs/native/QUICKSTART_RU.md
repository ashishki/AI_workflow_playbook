# Playbook: начните с задачи

Один вход — `$playbook` и описание желаемого результата. Агент изучает проект,
кратко предлагает подход и выполняет задачу в выбранных границах.

[Открыть стартовую страницу](start.html): поле задачи, ручные настройки и три
карточки частых сценариев. Скачанный `start.html` работает без сервера и интернета.
Он составляет запрос для вставки в Codex; сам не читает репозиторий и не запускает
агента. Можно обойтись без страницы и написать прямо в Codex:

```text
$playbook Исправь форму записи: на телефоне кнопка выходит за границы.
Сохрани оформление и проверь отправку, ошибку email и внешний вид.
```

Агент сообщает, например: «Существующий проект · исправить · автоматически».
Для ясной задачи он продолжает работу. Любую настройку можно изменить обычной
фразой, в том числе во время работы.

## Три независимых выбора

| Что выбираем | Варианты | Если не указать |
|---|---|---|
| Контекст | Новый / существующий проект | Агент смотрит файлы и задачу |
| Действие | Создать / исправить / проверить | Агент определяет желаемый результат |
| Процесс | Автоматически / сначала план / расширенный контроль | Агент предлагает соразмерный процесс |

**Автоматически:** реализовать → проверить → исправить найденное → показать итог.
«Быстро» означает меньше промежуточных документов и вопросов; проверка остаётся.

**Сначала план:** изучить, предложить изменения и проверки, остановиться до записи
файлов. Для реализации нужен следующий запрос пользователя.

**Расширенный контроль:** явные критерии, проверки важных ошибок и регрессий,
дополнительное review там, где оно доступно и оправдано. Недоступный независимый
review обозначается честно. Согласование каждого локального шага не требуется.

Действие «Проверить» даёт замечания, не разрешая автоматически исправлять код.
«Проверить + сначала план» — сначала предложить способ проверки и остановиться.
Новая функция в старом репозитории остаётся работой в существующем проекте.

## Подключение текущего preview

**Версия `0.1.0-preview.2` — исходный кандидат, публичного релиза нет.**
Реальные испытания уже проведены, но массовая установка ещё не подтверждена.
Публичная раздача ждёт выбора [прав на использование](../LEGAL_STATUS.md) и
проверки install/remove на заявленных hosts. Ниже путь для разрешённого scratch repo.

Будущий основной способ — штатная установка одного Codex plugin. Каталог этого
пакета пока не опубликован. Наличие manifest в папке не означает установку.

Для исходного preview откройте Codex в scratch repo и попросите:

```text
Прочитай /абсолютный/путь/AI_workflow_playbook/plugins/playbook-native/skills/playbook/SKILL.md
и подключи Playbook к текущему репозиторию. Сохрани существующие инструкции
и мои изменения. Покажи доступные проверки и ограничения среды.
```

При доступной записи агент копирует две папки skills в `.agents/skills` и добавляет
один небольшой блок в действующий `AGENTS.md` либо root override. Когда plugin
уже предоставляет skills, локальные копии не нужны. Старый initializer не нужен.
В новой сессии проверьте обнаружение `playbook` и `playbook-frontend` через `/skills`.

**Обнаруженное ограничение:** в испытанном `codex exec --sandbox workspace-write`
запись в `.agents` защищена. Подключение останавливается, сохраняя файлы; это не
успешная установка. Нужна штатная установка средствами host или разрешённое
пользователем размещение skills. Не отключайте sandbox ради инструкции. Если
skills уже установлены, plan/check работают без создания блока проекта.

## Проверка результата

Достаточный итог: что изменилось, какие проверки реально выполнены, что осталось
непроверенным. Для UI агент должен открыть именно изменённое приложение, пройти
сценарий и ошибку, проверить нужные размеры и посмотреть свежие screenshots.
Успешный build не заменяет эту проверку.

Browser tool должен быть доступен именно агенту, а не только обычному терминалу.
Наш пилот показал: даже установленный MCP может требовать отдельного разрешения
на навигацию. При отказе агент сообщает «UI не проверен»; дополнительные инструкции
не устраняют ограничение доступа. Встроенный browser описан для desktop; CLI/IDE
нужен отдельный доступный инструмент. [OpenAI Browser](https://developers.openai.com/codex/browser).

MCP не обязателен. Он уместен, если конкретной задаче нужен доступ к Figma,
DevTools или другим данным и доступные средства недостаточны. Не нужно ставить
каталог инструментов или менять global config при каждом подключении.

## Обновить или убрать

Попросите `$playbook` обновить пакет из выбранной версии или удалить его из repo.
Агент сохраняет пользовательские правки, удаляет только свой блок и известные
неизменённые файлы. Plugin обновляется/удаляется средствами host; его отключение
само по себе не убирает проектный блок. Полный lifecycle ещё требует host trials.
