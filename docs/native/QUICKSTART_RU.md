# Playbook: от задачи до результата

Опишите, что хотите получить. Playbook помогает Codex организовать работу,
сделать задачу, проверить результат и объяснить, что получилось. Программировать
или разбираться во внутренних правилах Playbook для первой пробы не требуется.

**Работа происходит в Codex:** туда вы отправляете задачу и там общаетесь с
агентом. Стартовая страница Playbook — инструкция и помощник для первого запроса;
она не является отдельным чатом. Потом можно сразу начинать в Codex.

## Первый запуск

1. Распакуйте пробный архив Playbook целиком и откройте `START.html` двойным щелчком.
2. Откройте приложение ChatGPT на компьютере, войдите в аккаунт и выберите Codex.
   [Официальная инструкция установки и входа](https://learn.chatgpt.com/docs/quickstart?setup=app).
3. Создайте локальный проект с папкой **«Мой проект»** из архива. Выберите её
   основной папкой проекта — в ней уже находятся инструкции Playbook.
   [Как выбрать папку](https://learn.chatgpt.com/docs/projects).
4. Опишите задачу в чате Codex или возьмите учебный пример на стартовой странице.

```text
Playbook, сделай небольшой учебный сайт преподавателя английского:
услуги, цены и форма заявки. Пока без оплаты и реальной отправки заявок.
Сделай удобно на телефоне, проверь форму и покажи, как открыть результат.
Я не программист.
```

Агент кратко объяснит подход и начнёт работу. Если для задачи нужен ваш выбор,
объяснит его простыми словами. В первой пробе не нужно открывать терминал,
копировать скрытые папки или настраивать MCP. Доступ к Codex нужен отдельно;
архив не включает аккаунт или оплату его использования.

**Статус: `0.1.0-preview.5`, пробный комплект для разрешённого тестирования.**
Публичного выпуска пока нет. Если у вас только этот репозиторий, а не комплект,
[сборка архива описана для сопровождающего](../../distribution/native/README.md).
Один скачанный [start.html](start.html) помогает составить запрос, но не содержит
папку проекта. Он работает без сервера, не читает ваши файлы и не запускает агента.

## Windows, macOS и Linux

Комплект один для трёх систем. В Windows выберите у ZIP «Извлечь всё»; в macOS
откройте архив двойным щелчком; в Linux используйте извлечение в файловом менеджере.
Затем откройте `START.html` в обычном браузере. Скачанный ZIP сначала нужно
распаковать: открытая страница внутри архива не подключает проект.

После изменений кода Playbook автоматически запускает отдельного ревьюера через
Role Runner. Он проверяет результат независимо от автора изменений; агент
исправляет подтверждённые замечания. Быстрый режим сохраняет и тесты, и ревью.
Самостоятельно выбирать роли или разбирать служебные файлы не требуется.

Для этой проверки в среде агента должны быть **Python 3.10+ и авторизованный
Codex CLI**. Агент проверит их наличие. Доступ к desktop сам по себе не доказывает
наличие CLI. Если запуск недоступен, вы получите понятное объяснение ограничения,
а не сообщение о якобы успешной независимой проверке.

[Проверки платформ и оставшиеся ограничения](PLATFORMS_RU.md).

## Как управлять работой

Обычно достаточно задачи. Любой выбор можно изменить обычной фразой.

| Что хотите | Что написать |
|---|---|
| Новый проект | «Начни новый учебный проект» |
| Работа с готовым проектом | «Исправь форму в этом проекте» |
| Сделать новое | «Добавь страницу с расписанием» |
| Найти и исправить ошибку | «Кнопка на телефоне обрезается — исправь» |
| Только проверить | «Найди проблемы, пока ничего не исправляй» |
| Работать автоматически | «Сделай и проверь; промежуточные документы не нужны» |
| Сначала обсудить | «Сначала только план, файлы пока не меняй» |
| Проверить тщательнее | «Расширенный контроль: проверь ошибки и важные последствия изменений» |

Новый/существующий проект, создать/исправить/проверить и способ контроля — три
независимых выбора. Не нужно заполнять их все. На стартовой странице есть
необязательные настройки и карточки частых задач.

**Быстро** означает меньше промежуточных документов и ненужных вопросов,
с сохранением проверки результата. **Сначала план** останавливает работу до
изменений: чтобы продолжить, напишите «План подходит, реализуй».
**Только проверить** даёт замечания без автоматического исправления исходников.
Расширенный контроль добавляет обоснованные проверки, а не согласование каждого шага.

## Как понять, что всё получилось

В итоге вы должны получить способ открыть результат, короткое объяснение
изменений, список реально выполненных проверок и понятные ограничения.
Например: «Откройте этот файл. Форма и мобильный экран проверены. Заявки пока
никуда не отправляются».

Для сайта агент должен открыть изменённую страницу, попробовать основной
сценарий и ошибки, посмотреть внешний вид. Если браузер ему недоступен, он
должен сказать об этом; слова «проект собран» не означают, что интерфейс проверен.
Локальный учебный пример не становится опубликованным сайтом автоматически.

## Если уже есть свой проект

В `START.html` раскройте «У меня уже есть свой проект». Там готовый запрос,
который просит Codex установить Playbook штатным способом из включённой папки
плагина. После установки откройте свой проект в новом чате и опишите задачу,
начав с «Playbook». Учебную папку поверх существующего проекта не копируйте.

Этот путь проверен в Codex CLI 0.155.1 на Linux: установка, повторная установка,
обновление, удаление и обнаружение skills в новых сессиях. Окна установки desktop
и самостоятельный проход новичка ещё не испытаны. Если среда не позволяет
установку, агент объяснит следующий шаг; отключать защиту ради Playbook не нужно.

MCP — дополнительное подключение к инструментам и данным. Для начала оно
не требуется. Агент предложит его только для конкретной нужды, например
работы с макетом Figma, если имеющихся инструментов недостаточно.

## Продолжить, остановить, убрать

Завтра откройте ту же папку проекта и продолжите разговор. Можно сказать:
«Продолжим», «Сначала объясни», «Исправь только это» или «Остановись».
Если непонятно, отправьте:

```text
Playbook, я застрял. Проверь, какая папка открыта и доступен ли Playbook.
Объясни простыми словами один следующий шаг и как я пойму, что он сработал.
Ничего не устанавливай и не меняй настройки без моего запроса.
```

Чтобы убрать Playbook из проекта, попросите об этом агента. Он уберёт свои
инструкции, сохранив вашу работу. Ваши изменения самих skills сохраняются целой
резервной папкой, которая больше не активна. Установленный плагин удаляется
средствами Codex; это отдельное действие от удаления инструкций проекта.
