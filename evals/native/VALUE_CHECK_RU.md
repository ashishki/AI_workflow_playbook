# Проверка: нужен ли Playbook сверх обычного агента

План зафиксирован до новых model trials, 2026-09-19. База продукта `f342162`.
Используем существующий Harness Lab и Native command adapter. Новой лаборатории нет.

## Вопрос и три условия

Проверяем, помогает ли пакет инструкций получить правильный результат с меньшими
затратами. Упаковка, количество правил и зелёный CI преимуществом не считаются.

1. **plain:** обычный Codex с теми же общими настройками, без проектного Playbook.
2. **current:** Native preview.5 из `f342162`.
3. **lean:** сокращённые entry skill и project block; frontend, connection и
   Role Runner сохранены. Это кандидат preview.6, замороженный до испытаний.

Два новых сценария, которых не было в предыдущих Native trials:

| Задача | Пользовательский результат | Внешняя проверка |
|---|---|---|
| `booking` | Существующие записи сохранены; повтор запроса не создаёт дубль; занятый слот нельзя продать повторно | 8 групп: прежние данные, другой процесс, повтор, конфликт, reuse ключа, нормализация, неверный ввод, повреждённые данные |
| `contacts` | Файл рассылки содержит только разрешённые контакты; исходник сохранён | 7 групп: строгое согласие, CSV/кириллица, дубли и адреса, пустой экспорт, совпадение путей/ссылка, повреждённый JSON |

Правила задачи находятся в одинаковом README каждой fixture. Внешний оценщик
не передаётся участнику в workspace. Это не защита от злонамеренного чтения
всего host filesystem; такой противник не является предметом испытания.
Проверены исходные ошибки, правильные контрольные реализации и четыре мутанта.
Контрольные реализации не входят в model fixtures.

## Ограничения и бюджет

Проверяем **инструкции без независимого ревью**: вложенный Codex в этом host уже
проверенно недоступен. Обоим условиям даётся одинаковое явное ограничение не
запускать reviewer и не менять разрешения. Это ablation, не полный продуктовый
цикл и не оценка полезности самого Role Runner. Автоматическое ревью в продукте
сохраняется по решению автора. Браузер этим двум задачам не требуется.

Модель/effort — существующие `gpt-6-astra/xhigh`, CLI 0.155.1; workspace-write,
approval never. Без смены глобальных инструкций, разрешений, модели и credentials.
Baseline использует обычный текущий host с его общими skills/instructions;
это не чистый аккаунт новичка. Claude Code в сравнении не участвует.

По 2 попытки × 2 задачи × 3 условия = **не более 12 основных запусков**.
Лимит каждого — 240 секунд; human corrections = 0 по устройству эксперимента.
Это не измерение потребности настоящего новичка в помощи. Один worker выполняет
условия последовательно: plain/current/lean, затем lean/current/plain.
Порядок задач чередуется. Исходники, scorer, prompts и пакеты фиксируются хешами
до запуска и сохраняются без изменений до окончания batch. Нет перезаписи неудач
или дополнительных попыток ради проходящего результата. Два одинаковых отказа
инициализации подряд останавливают работу; таймауты учитываются в общем бюджете.

## Решение по результатам

- Сначала сохранность данных и выполнение правил, затем честность финального
  ответа и полезность инструкции «как пользоваться». Последние читаем вручную;
  свободный текст не объявляем проверенным из `false_success_rate=0`.
- Считаем токены input/cached/output, число инструментальных вызовов, время,
  валидные/невалидные исполнения. Неизвестная цена и неполный usage — unknown.
  Время зависит от нагрузки и кеширования; не превращаем его в обещание скорости.
- Удаление generic-инструкций принимаем, если на всех четырёх попытках lean
  не добавляет подтверждённых дефектов/потери данных относительно current.
  При одинаковом качестве меньший footprint полезен сам по себе; рост медианных
  token/tool затрат более чем на 20% требует объяснения или следующего сравнения.
  Порог — ориентир этого локального решения, не статистический тест.
- Преимущество над plain требует наблюдаемой пользы в результатах, проверках или
  затратах. Ничья означает «польза пока не показана», а не доказательство равенства.
  Пакет с неустановленной пользой остаётся экспериментальным; новая обёртка его не спасает.
- Любой неполный/заблокированный опыт ограничивает вывод. Четыре попытки на условие
  не доказывают преимущество на произвольных задачах, платформах и моделях.

## Вход в продукт

Уже наблюдавшаяся проблема пользователя: START создаёт лишний перенос текста
между браузером и агентом. Основной путь — открыть подготовленный проект в Codex
и написать задачу. START остаётся необязательной помощью, режимы меняются в чате.
Это UX-решение по прямой обратной связи; model trials не являются его usability-тестом.

Штатные skills и их автоматическая загрузка уже есть в
[Codex](https://learn.chatgpt.com/docs/build-skills) и
[Claude Code](https://code.claude.com/docs/en/skills). У Claude также описаны
встроенные проверки запуска приложения. Эти факты подтверждают, что само наличие
skill или reviewer не является уникальным преимуществом Playbook. Совместимость
нашего пакета с Claude этим чтением документации не установлена.
